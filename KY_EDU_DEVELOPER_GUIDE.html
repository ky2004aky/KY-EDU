KY EDU Chapter 2: Database Design & MongoDB Schema

2. Database Engineering (MongoDB 8.0)

The persistence layer is structured around MongoDB 8.0 under the database named ky_edu_db. NoSQL document modeling is selected because government examinations contain multi-dimensional nested structures: age relaxation rules, multiple selection stages, subject weightages, and authoritative book recommendations.

Primary Collections Overview

1. exams Collection
Stores 32+ central & state examinations with conducting bodies, 7th CPC salary, vacancies, detailed eligibility rules, stages with marks deduction, and subject booklists.
2. careers Collection
Contains 14 career pathways spanning Science, Commerce, Arts, ITI, Defense, Law, and Aviation with 56 structured multi-phase milestones, top roles, and entrance exams.
3. users Collection
Stores student profiles: Name, Age, Standard/Stream (10th, 12th PCM, Polytechnic, B.Tech), Department, Email, hashed password, and personalized exam bookmarks.
4. updates & audit_logs Collections
Live notification ticker alerts (Admit Cards, Application Windows, Answer Keys) and admin audit trails recording all CRUD actions on the portal.

KY EDU Chapter 2: Database Pipeline & Seeding

Database Seeding Pipeline

To eliminate escaping errors and ensure rapid maintenance, the dataset is stored in backend/data/seed_data.json (166 KB) containing 32 examinations, 14 career pathways, and 10 live circulars. The PHP seeder script reads, decodes, and inserts in bulk.

Database Singleton Class (backend/config/Database.php)

<?php
namespace App\Config;

use MongoDB\Driver\Manager;
use MongoDB\Driver\BulkWrite;
use MongoDB\Driver\Query;
use MongoDB\Driver\Command;

class Database {
    private static ?Database $instance = null;
    private Manager $manager;
    private string $dbName;

    private function __construct() {
        $uri = getenv('MONGODB_URI') ?: 'mongodb://localhost:27017';
        $this->dbName = getenv('MONGODB_DB') ?: 'ky_edu_db';
        $this->manager = new Manager($uri);
    }

    public static function getInstance(): Database {
        if (self::$instance === null) {
            self::$instance = new Database();
        }
        return self::$instance;
    }

    public function insertMany(string $collection, array $documents): int {
        $bulk = new BulkWrite();
        foreach ($documents as $doc) {
            $bulk->insert($doc);
        }
        $result = $this->manager->executeBulkWrite("{$this->dbName}.{$collection}", $bulk);
        return $result->getInsertedCount();
    }

    public function find(string $collection, array $filter = [], array $options = []): array {
        $query = new Query($filter, $options);
        $cursor = $this->manager->executeQuery("{$this->dbName}.{$collection}", $query);
        $results = [];
        foreach ($cursor as $doc) {
            $results[] = $this->formatDoc($doc);
        }
        return $results;
    }
}

KY EDU Chapter 3: Backend REST API Architecture

3. Backend Development (PHP 8.2 REST API)

The backend is designed without heavy bloated frameworks to achieve sub-millisecond execution times. It exposes standard HTTP verbs (GET, POST, PUT, DELETE, OPTIONS) and strictly returns standard JSON envelopes.

CORS Preflight & Header Security (backend/config/cors.php)

Browsers send an HTTP OPTIONS preflight check before transmitting custom headers. To support student and admin sessions, the CORS filter explicitly permits the custom authentication headers. 

<?php
namespace App\Config;

function initCors(): void {
    header("Access-Control-Allow-Origin: *");
    header("Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS");
    header("Access-Control-Allow-Headers: Content-Type, Authorization, X-User-Token, X-Admin-Token, Accept");
    header("Content-Type: application/json; charset=UTF-8");

    // Respond immediately to browser preflight check
    if ($_SERVER['REQUEST_METHOD'] === 'OPTIONS') {
        http_response_code(200);
        exit(0);
    }
}

function jsonResponse(array $data, int $statusCode = 200): void {
    http_response_code($statusCode);
    echo json_encode($data, JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT);
    exit;
}

KY EDU Chapter 3: Smart Eligibility Calculation Engine

Smart Eligibility Calculation Algorithm

The core differentiator of KY EDU is the Government Eligibility Matcher. It calculates multi-variant compatibility by factoring in:

  • Standard Age Ceilings (e.g. 18-32 years for General category).
  • Statutory Category Relaxations: OBC (+3 Years), SC/ST (+5 Years), PwD (+10 Years).
  • Hierarchical Education Equivalence: A Graduate automatically fulfills 10th and 12th prerequisites.
  • Academic Stream Specializations: PCM matches Defense/Engineering; B.Sc Agri matches AFO; LL.B matches Judiciary.

Calculation Logic & Age Relaxation Formula

<?php
// Statutory Relaxation Matrix
$relaxation = 0;
if ($category === 'OBC') $relaxation = 3;
elseif ($category === 'SC' || $category === 'ST') $relaxation = 5;
elseif ($category === 'PwD') $relaxation = 10;

foreach ($exams as $exam) {
    $minAge = $exam['eligibility']['minAge'] ?? 18;
    $maxAge = ($exam['eligibility']['maxAge'] ?? 32) + $relaxation;
    
    // 1. Age Verification
    $isAgeEligible = ($userAge >= $minAge && $userAge <= $maxAge);

    // 2. Education Hierarchy Matching
    $examEdu = strtolower($exam['eligibility']['educationLevel'] ?? '');
    $userEdu = strtolower($userQualification);
    $isEduEligible = checkEducationHierarchy($userEdu, $examEdu);

    // 3. Stream Alignment Matching
    $examStream = strtolower($exam['stream'] ?? 'any');
    $isStreamEligible = checkStreamCompatibility($userStream, $examStream);

    $isEligible = $isAgeEligible && $isEduEligible && $isStreamEligible;
    $matchScore = $isEligible ? 95 : ($isAgeEligible ? 65 : 35);
}

KY EDU Chapter 4: Hybrid Online & Offline Architecture

Hybrid Architecture: Live API + Cloud-Demo Fallback

When deploying full-stack web applications on static platforms like GitHub Pages, the browser operates over https:// and blocks insecure local calls (http://localhost:8000). To ensure the site runs 100% interactively everywhere, KY EDU implements a Dual-Mode Hybrid Service Engine.

Hybrid Execution Flow (frontend/src/services/api.js)

1. Online Mode (Localhost / Live Server):
• request() connects directly to PHP REST backend on localhost:8000.
• Writes and reads live from MongoDB 8.0 instance.

2. Static / GitHub Pages Mode (Fallback Triggered on TypeError / Network Error):
• Automatically catches TypeError: Failed to fetch.
• Exams & Careers: Instant fallback to frontend/src/data/fallbackData.json (32 exams, 14 careers).
• Student Authentication: Stores registered users in localStorage (ky_edu_mock_users).
• Eligibility Matcher: Client-side JS evaluator runs age relaxation matrix in-browser.
• Admin Control: Instant mock SuperAdmin session with PIN 123456.

Implementation in api.js

export const api = {
  userLogin: async (credentials) => {
    try {
      // 1. Try Live PHP REST API
      return await request('user_auth.php?action=login', {
        method: 'POST',
        body: JSON.stringify(credentials)
      });
    } catch (err) {
      // 2. If Network / Mixed-Content Error on Static Host, Fallback to LocalStorage
      if (err.name === 'TypeError' || !err.status) {
        const users = JSON.parse(localStorage.getItem('ky_edu_mock_users') || '[]');
        const user = users.find(u => u.email === credentials.email && u.password === credentials.password);
        if (user) {
          return { success: true, token: 'local_token_' + Date.now(), user };
        }
        // Auto-provision demo session for friction-free testing
        const demoUser = {
          _id: 'demo_' + Date.now(),
          name: credentials.email.split('@')[0] || 'Student',
          email: credentials.email,
          age: 21,
          std: '12th Science (PCM)',
          department: 'Science & Technology / Engineering'
        };
        return { success: true, token: 'local_token_' + Date.now(), user: demoUser };
      }
      throw err;
    }
  }
};

KY EDU Chapter 5: Step-by-Step Installation & Setup

5. Step-by-Step Setup & Run Guide

Follow this exact sequential procedure to set up the development environment, seed the database, and launch both the PHP backend and React frontend.

Prerequisites Checklist

  • Node.js: v18.0 or higher installed (node -v, npm -v).
  • PHP: v8.2 or higher installed with mongodb, curl, openssl extensions.
  • MongoDB: Community Server v7.0 or v8.0 running on localhost:27017.
  • Git: Git for Windows or GitHub Desktop.

Step-by-Step Terminal Execution

1 Clone Repository & Enter Directory

git clone https://github.com/ky2004aky/KY-EDU.git
cd KY-EDU

2 Start MongoDB Service

Ensure the local MongoDB daemon is active. On Windows:

net start MongoDB
# Or verify via mongosh:
mongosh --eval "db.version()"

3 Seed the MongoDB Database

Start a temporary PHP server and trigger the database seeding endpoint:

# In root directory, start PHP backend
php -S localhost:8000 -t backend

# In a separate terminal or browser, trigger seeding:
curl http://localhost:8000/api/seed.php
# Output: {"success": true, "stats": {"examsInserted": 32, "careersInserted": 14, "updatesInserted": 10}}

4 Install Frontend Dependencies

cd frontend
npm install

5 Launch Development Server

npm run dev
# Vite will launch on http://localhost:5173
One-Click Windows Launcher: Double-clicking start_ky_edu.bat in the project root automatically launches both the PHP backend on port 8000 and the Vite frontend on port 5173 in concurrent windows!

KY EDU Chapter 6: Cloud Deployment & GitHub Pages

6. Deployment & Cloud Hosting Guide

KY EDU is pre-configured for automated continuous deployment using GitHub Actions and GitHub Pages.

1. GitHub Pages Automated CI/CD Workflow

File: .github/workflows/deploy.yml. Whenever changes are pushed to the main branch, GitHub Actions builds and publishes the production site automatically. 

name: Deploy KY EDU to GitHub Pages

on:
  push:
    branches: ["main"]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
          cache-dependency-path: frontend/package-lock.json
      - run: cd frontend && npm ci
      - run: cd frontend && npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: frontend/dist

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    needs: build
    steps:
      - uses: actions/deploy-pages@v4

2. Vite Relative Base Configuration

In frontend/vite.config.js, setting base: './' ensures that all bundled scripts and stylesheets load cleanly whether hosted at root or on a subpath like /KY-EDU/: 

export default defineConfig({
  base: './', // Ensures relative assets loading on GitHub Pages
  plugins: [react(), tailwindcss()],
  server: {
    port: 5173,
    proxy: { '/api': { target: 'http://localhost:8000', changeOrigin: true } }
  }
});
